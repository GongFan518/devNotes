去年上线的一个活动页，进来第一件事是把十几个 `useState` 摊开读一遍。读到第七个的时候我已经不知道哪个是真正的来源、哪个只是它的副本了。页面能跑，但没人敢动。

## 症状

这类组件通常有同一个形状：一个「主状态」，三四个由它派生出来的状态，以及若干用来同步它们的 `useEffect`。每次用户操作，要记得同时改三处，漏一处就出一次诡异的错。

真正的问题不是组件太长，而是**同一份事实被存了两遍**。

## 两次搬家

第一次搬，是把派生状态全部删掉，改成渲染时算。这一步通常能砍掉一半代码，而且几乎没有风险。

第二次搬，才动主状态。判断标准很简单：这个状态是不是只有这一个组件关心？如果答案是否，它就不该在这里。

```ts
// 之前：组件里三份副本
const [items, setItems] = useState([])
const [count, setCount] = useState(0)
const [isEmpty, setIsEmpty] = useState(true)

// 之后：只留事实
const items = useItems()
const count = items.length
```

「渲染时算」这四个字听起来很朴素，但它把一致性从人的记性转移到了代码结构上。之后每一次改动，都不需要再确认有没有人忘了同步。

## 一点后悔

如果重来，我会在最开始就把这些状态放进一个 store，哪怕当时只有一个页面用它。代价是多写二十行，收益是半年后不必重读自己的代码。
