排查过程不值得写，结论值得。

## 发生了什么

一个列表接口在 Next.js 15 里默认不缓存。升级的时候没人注意这条变更，因为在本地开发环境里，请求数量和缓存行为根本看不出来——本地只有你一个人点。

上线之后每个用户的每次访问都会打到后端。接口本身没挂，延迟也正常，只是请求量涨了四倍。

## 现在的写法

现在我在所有跨域 `fetch` 上强制写明缓存意图，哪怕写的是不缓存：

```ts
const res = await fetch(url, { cache: 'force-cache', next: { revalidate: 300 } })
```

显式写出来不是为了机器，是为了下一个读到这段代码的人（包括三个月后的我）知道这里有意做过决定。

## 一个更笨但更有效的办法

给所有对外接口加了一个请求计数面板，超过阈值就报警。不优雅，但那次之后我没有再被这类问题偷袭过。
