# 站点风格：卡片盒

全站已经换成 **卡片盒** 这一套：牛皮纸桌面、打了孔的卡片、盖上去的日期章。这篇文章记录它由什么组成、改在哪里，以及等你接手时最可能想动的地方。

## 三个基本件

整套界面的材质只有三样东西，所有页面都是它们的组合：

1. **桌面** —— 页面底色 `#dcd5c6`，带一层很淡的斜纹。它不是背景色，是"放卡片的桌子"。
2. **卡片** —— `#fcfaf2` 的纸，1px 描边，硬投影（`2px 3px 0`，不是模糊阴影），左上角一个打孔。
3. **日期章** —— 红棕色的方框，微微歪 3 度，像盖上去的。

卡片会轻微旋转（奇偶列方向相反）、偶数卡片下沉 14px，这样一叠卡片才不会像表格。

## 字体

- 标题：**思源宋体**（Noto Serif SC），600 字重
- 正文：**思源黑体**（Noto Sans SC），16.5px / 行高 1.95
- 标签、日期、编号：**等宽字体**（Courier New / Consolas）

全部用系统已装字体，没有网络字体请求，所以首屏不会闪字。想换字体只需要改 `css/kraft.css` 顶部的 `--k-serif` / `--k-sans` / `--k-mono` 三个变量。

## 页面结构

| 页面           | 长什么样                                                  |
| -------------- | --------------------------------------------------------- |
| `/`            | 顶部一张"盒盖说明卡"，最新一篇横跨两列，其余两列排开      |
| `/blog`        | 左边一张索引卡（全部 + 各标签计数），右边卡片竖排         |
| 文章页         | 一张大卡把正文整个装下，正文栏宽 38em，页脚放标签、上下篇 |
| `/tags`        | 一面卡片标签墙，每个标签带篇数                            |
| `/about`       | 左边一张"名片"（头像 + 名字 + 社交），右边正文            |
| `/collections` | 合集卡片；点进去是这个合集里的文章，按你排好的顺序        |
| 404            | 一张卡里放超大 404                                        |

## 只有浅色

**没有做夜间模式**，这是刻意的：卡片盒的质感全在纸和桌子的关系上，深色版需要重配一整套"深色卡纸 + 暖光"，不是加个滤镜能解决的。`app/theme-providers.tsx` 里已经 `forcedTheme="light"`，页头的夜间切换按钮也拿掉了。

以后要加的话，做法是在 `css/kraft.css` 里给 `html.dark` 补一组变量覆盖，然后把 `forcedTheme` 去掉——所有颜色都走变量，不用改结构。

写作只涉及 `data/blog/*.mdx`，frontmatter 里 `title / date / tags / summary / authors` 五项就够。**日常怎么写文章、怎么配合集，看 [authoring-guide.md](authoring-guide.md)。**

## 合集

「合集」取代了模板原来的「项目」。它解决的是：文章按标签分太散，但有些文章在讲同一件事，需要一条人工排好的阅读顺序。

配置在 `data/collections.ts`，就是个数组：

```ts
{
  slug: 'rebuilds',              // URL：/collections/rebuilds
  title: '重写的现场',
  description: '一到两句话说清这组的共同点',
  posts: [
    '把 React 的状态从组件里搬出来',   // ← 填标题
    'three-attempts-at-a-homepage',  // ← 或者填 slug，两种都认
    '一个 fetch 没写 cache，线上多了三千次请求',
  ],
}
```

几个要点：

- **顺序就是数组顺序**。页面上的 01/02/03、以及点进文章后底部的上一篇/下一篇，全按这个来。
- **可以跨标签**，一个合集里的文章不需要有共同标签。
- **两种写法都认**：slug 或完整标题，写错只会在终端警告并跳过，不会把页面搞挂。
- 同一篇文章可以出现在多个合集里，互不影响。
- 合集只收已发布的文章，草稿会被跳过。

三层页面：

| 地址                              | 是什么                                                                  |
| --------------------------------- | ----------------------------------------------------------------------- |
| `/collections`                    | 所有合集                                                                |
| `/collections/<slug>`             | 这个合集里的文章，带序号                                                |
| `/collections/<slug>/<文章 slug>` | 在合集语境下读文章：顶部标「合集 · 名字 · 2/3」，底部上下篇只在合集内走 |

合集里的文章页和 `/blog/...` 是同一篇内容，但 canonical 指向 `/blog` 那一份，不会造成重复收录。从 `/blog` 点进去看到的仍然是全站倒序的上下篇——**同一个页面，两种上下文**。

## 搜索

搜索不再用 `pliny` 的 kbar（它把深色 Tailwind 类写死在弹窗里，没有可覆写的钩子），改成自带的 `components/Search.tsx`：

- 索引仍然由 contentlayer 生成到 `public/search.json`，逻辑没变
- 弹窗、结果列表、键盘操作全部用 `css/kraft.css` 里的 `.k-search*` 定义
- 支持 `⌘K` / `Ctrl+K` 开合、`↑↓` 选择、`↵` 打开、`esc` 关闭、点遮罩关闭
- 首次打开才去拉索引，关闭时锁滚动

## 头像

关于页那张卡片现在是一个「印章位」：没配 `avatar` 时显示站名首字的圆形占位。想换成真人照片，把图片放进 `public/static/images/`，然后改 `data/authors/default.mdx`：

```yaml
avatar: /static/images/avatar.jpg
```

## 已知情况

**本地构建要和 dev server 分开跑。** 两者共用 `.next` 目录，一边 `next dev` 一边 `next build` 会让构建随机报 `Cannot find module for page`（我在这上面绕了很久）。正确姿势：

```bash
# 先停掉 next dev，再构建
yarn build
```

停掉 dev 之后干净构建可以通过（包含全部中文标签页）。另一个小提醒：`yarn build` 里的 `postbuild` 才会生成 `public/feed.xml`，单独跑 `next build` 不会。
