# 首页方案 · 四个方向

> 记录用：这是选型阶段的四个方向，最终选定 **03 卡片盒**。落地后的实际实现见 [site-theme.md](site-theme.md)。
>
> ⚠️ 四个原型页（`/design`、`app/design/`、`components/design/`、`css/skins.css`）**只在本地保留，没有提交到仓库**（见 `.gitignore`），所以线上不会出现，新克隆的仓库里也没有。想看的话只能在你自己这台机器上跑 `yarn dev`；想永久留着就把 `.gitignore` 里那三行删掉再提交。

这一轮的目标不是"把首页做好看"，而是先定**方向**：同一个博客，用四种不同的信息结构去呈现，选定一个再往下做全站。

看的地方：

- `/design` — 四个方案的总览（**仅本地，未提交**）
- `/design/v1` … `/design/v4` — 单个方案（底部有切换条）
- 任意方案后面加 `?bare=1` — 隐藏切换条，看到干净的页面
- `/` — 原来的模板首页，还没动

## 四个方向

### 01 稿纸 Manuscript paper

整页是一张方格稿纸：正文用**仿宋**写在 32px 的格子上，左右各一道红色页边线。

这个方向的判断是——**把技术文章当文章写**。信息密度最低，但读起来最像在读东西，而不是在刷列表。适合你希望读者真的读进去、并且你会持续写长文的情况。

代价：一屏看不到几篇；文章数量少于十几篇时页面会显得空。

### 02 蓝图 Drawing sheet

深蓝图纸、图框、标题栏，文章排成图纸目录（图号 / 图名 / 分类 / 日期）。

判断是——**这是一个工程师的工作台**。四个方向里辨识度最高，一眼就能记住。

代价：深色底不适合长文阅读，它只适合当门面；进到文章页还得换成浅色。中文压在蓝图上要小心，容易显硬。

### 03 卡片盒 Index cards

牛皮纸桌面上摊着打了孔的手写卡片，日期像盖上去的章，卡片有轻微的歪斜和硬投影。

判断是——**这是一盒随手记下的纸片**。和"笔记"这件事本身贴得最近，也最有温度，适合技术 + 随笔混写。

代价：卡片形式会限制长文的呈现；两列布局在文章变多以后需要分页策略。

### 04 编年 Chronicle

按年份竖排，年份用超大字号压在左侧，每篇只留日期、标题、一句话、标签。

判断是——**这是一个会长大的档案**。最耐看，结构最诚实，三年后加了五十篇文章也不会变形。

代价：偏冷、偏理性，个人气质要靠文字自己撑起来，视觉上不抢戏。

## 配色与字体

四个方向都只在本地系统字体里选，没有引入网络字体——中文用系统里的**思源黑体 / 思源宋体 / 仿宋 / 楷体**，西文和数字用 Consolas / Helvetica，因此首屏不会因为下载字体而闪烁。

| 方案   | 底色 / 主色                 | 强调色           | 标题                    | 正文         |
| ------ | --------------------------- | ---------------- | ----------------------- | ------------ |
| 稿纸   | `#f2f0e9` 桌 / `#fdfcf8` 纸 | `#b8433a` 页边线 | 思源黑体 900            | 仿宋 17/32   |
| 蓝图   | `#0f2e4a`                   | `#f0b429`        | 等宽 + 等线             | 思源黑体 300 |
| 卡片盒 | `#dcd5c6` 牛皮纸            | `#a23a32` 印章   | 思源宋体 600            | 思源黑体 14  |
| 编年   | `#f1f2ef`                   | `#0e6b5c`        | 思源黑体 600 + 超大数字 | 思源黑体 15  |

如果要换掉系统字体，只需要改 `css/skins.css` 顶部的变量，或者用 `next/font/local` 引入思源字体文件。

## 代码位置

| 文件                                                | 作用                                                      |
| --------------------------------------------------- | --------------------------------------------------------- |
| `app/design/page.tsx`                               | 四个方案的总览页                                          |
| `app/design/[variant]/page.tsx`                     | 按 `v1`–`v4` 渲染对应方案                                 |
| `app/design/layout.tsx`                             | 引入 `css/skins.css`                                      |
| `components/design/V1Paper.tsx` … `V4Chronicle.tsx` | 四个首页                                                  |
| `components/design/format.ts`                       | 日期格式化（`2026.09.14` / `09.14` / `2026 年 9 月`）     |
| `css/skins.css`                                     | 全部样式，按 `.sk-v1` … `.sk-v4` 隔离，不影响站点其他页面 |
| `scripts/shoot.mjs`                                 | 用无头 Chrome 截图，`node scripts/shoot.mjs`              |

这些方案页刻意绕开了模板自带的 Header / Footer（用 `body:has(.sk-root)` 把它们隐藏掉），所以它们是完全独立的页面。**选定方向之后，正确的做法不是把这个页留在这儿，而是把它拆成 `Header / Footer / ListLayout / PostLayout` 四件套，替换掉模板的对应文件。**

## 一个已知问题

模板自带的水合（hydration）不匹配，来自 `pliny` 的搜索组件（headlessui 的 portal 在服务端和客户端渲染结果不一致）。**每个页面都有**，和这四个方案无关，但在开发环境会让页面整体重绘一次。等定了方向，建议一并处理掉——它现在是全站首屏最明显的性能问题。
