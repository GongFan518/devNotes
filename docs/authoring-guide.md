# 日常使用手册

这份文档只讲**你怎么用**：发文章、调标签、配合集、改站名。不涉及改代码。

---

## 0. 两条命令

```bash
yarn dev     # 本地预览，改文件会自动刷新
yarn build   # 生产构建（发布时 Vercel 会自动跑，本地一般不用）
```

打开 http://localhost:3000 看效果。

> ⚠️ **跑 `yarn build` 之前一定要先停掉 `yarn dev`。**
> 两者共用 `.next` 目录，同时跑会随机报 `Cannot find module for page`。这个坑我踩过，不是你的代码坏了。

发布就是 `git push`。Vercel 会自动构建并上线，不需要你做别的。

## 1. 发一篇新文章

### 第一步：在 `data/blog/` 下新建一个 `.mdx` 文件

文件名就是网址。比如建 `data/blog/my-new-post.mdx`，文章地址就是 `/blog/my-new-post`。

**建议用英文短横线命名**（`how-i-learned-css.mdx`），因为文件名会直接进 URL。

也可以用子目录来归类，`data/blog/2026/xxx.mdx` 的地址是 `/blog/2026/xxx`。

> 扩展名必须是 `.mdx`。写成 `.md` 不会被识别，文章不会出现，也不会报错——很容易白找半天。

### 第二步：写 frontmatter

复制这个模板，改内容：

```mdx
---
title: 文章标题
date: '2026-11-27'
tags: ['CSS', '随笔']
authors: ['default']
summary: 一句话说清这篇文章讲什么，会显示在卡片和搜索结果里。
---

正文从这里开始。

## 小标题

第一段……
```

### 第三步：写正文

普通 Markdown 就行。这个站额外支持：

**代码块**（会高亮）

````mdx
```ts
const items = useItems()
```
````

**提示框**

```mdx
> [!NOTE]
> 这是一个提示。

> [!WARNING]
> 这是一个警告。
```

**数学公式**（KaTeX）

```mdx
行内 $E = mc^2$，独立成段：

$$
\sum_{i=1}^{n} i = \frac{n(n+1)}{2}
$$
```

**插图**——图片放进 `public/static/images/`，然后：

```mdx
![图片说明](/static/images/xxx.png)
```

也可以指定尺寸（更可控）：

```mdx
<Image src="/static/images/xxx.png" alt="图片说明" width={800} height={450} />
```

**表格**、**任务列表**（`- [x] 已完成`）、**脚注**（`[^1]`）都支持。

### 第四步：预览

保存文件，浏览器会自动刷新。看看卡片上的摘要在首页排得对不对。

## 2. frontmatter 字段全表

| 字段      | 必填     | 说明                                                             |
| --------- | -------- | ---------------------------------------------------------------- |
| `title`   | ✅       | 文章标题                                                         |
| `date`    | ✅       | 格式 `'2026-11-27'`，**要带引号**。决定排序和显示                |
| `summary` | 强烈建议 | 一两句话。显示在卡片、搜索结果、分享卡片上                       |
| `tags`    | 建议     | 数组，如 `['CSS', '随笔']`。标签页会自动生成                     |
| `authors` | 否       | 不写默认 `['default']`，即 `data/authors/default.mdx`            |
| `draft`   | 否       | 写 `draft: true` 就是草稿                                        |
| `images`  | 否       | 分享到微信/Twitter 时的封面图，如 `['/static/images/cover.png']` |
| `layout`  | 否       | 不写就是默认版式；写 `PostSimple` 会去掉作者那一栏               |
| `lastmod` | 否       | 最后修改日期，用在 sitemap 和结构化数据里                        |

### 关于草稿

`draft: true` 时：

- **本地预览能看到**（方便你检查）
- **线上不会出现**（首页、列表、标签、搜索、RSS 都没有）
- **合集里永远不出现**，哪怕你是本地预览

写完想发布，把 `draft: true` 这一行删掉就行。

## 3. 标签怎么用

### 加一个新标签

直接写在 frontmatter 里，不需要配置任何东西：

```yaml
tags: ['CSS', '设计', '新标签']
```

保存后会自动出现：`/tags` 页面多一项，侧边索引多一行，标签页 `/tags/新标签` 自动生成。

### 英文标签会自动变小写

`React` 会变成 `/tags/react`，`Next.js` 会变成 `/tags/nextjs`。这是 URL 规范化，页面上显示的仍是你的原始大小写。

### ⚠️ 最容易出错的地方：同一件事写成两个名字

`CSS` 和 `css`、`React` 和 `React.js` 会被当成**两个不同的标签**，各自有一半文章。

**定好一套写法，之后就照着用。** 如果要统一，就把所有文章里的那一个字符串全改掉。

### 改标签名

改所有文章 frontmatter 里的那个字符串即可。旧标签页会消失，新标签页自动出现，会有几条旧链接失效——通常无所谓。

### 删标签

把所有文章里的它删掉。如果它没有文章了，标签页会自然消失。

> 不要手动改 `app/tag-data.json`。它由系统根据文章自动生成，你改了下次会被覆盖。

## 4. 合集怎么配

文件：`data/collections.ts`

合集是「你手工挑的一组文章」，可以跨标签，**顺序由你决定**。

### 加一个合集

```ts
{
  slug: 'rebuilds',                    // URL：/collections/rebuilds
  title: '重写的现场',
  description: '一到两句话说清这组文章的共同点。',
  posts: [
    '把 React 的状态从组件里搬出来',        // ← 填标题
    'three-attempts-at-a-homepage',      // ← 或者填文件名（slug）
    '一个 fetch 没写 cache，线上多了三千次请求',
  ],
}
```

三个要点：

1. **`posts` 里两种写法都认**——文章标题，或者文件名（不含 `.mdx`）。混着用也行。
2. **顺序就是显示顺序**。页面上的 01/02/03、以及从这里点进文章后底部的上一篇/下一篇，全按这个数组。
3. 写错了不会白屏。终端会打印一条警告（告诉你哪个合集、哪个字符串找不到），那一项会被跳过。

### 可以做什么

- ✅ 跨标签：一个合集里的文章不需要有共同标签
- ✅ 同一篇文章可以被多个合集收录
- ✅ 草稿不会进合集（哪怕本地预览也不会）
- ✅ 合集数量、文章数量都没有限制

### 合集长什么样

| 地址                             | 内容                                                                      |
| -------------------------------- | ------------------------------------------------------------------------- |
| `/collections`                   | 所有合集                                                                  |
| `/collections/rebuilds`          | 这个合集的文章，带序号                                                    |
| `/collections/rebuilds/<文件名>` | 在合集里读文章：顶部标「合集 · 重写的现场 · 2/3」，底部上下篇只在合集内走 |

**注意**：合集里读文章和 `/blog` 里读文章是同一篇内文，但上下篇不一样——从合集进就是合集顺序，从笔记列表进就是全站时间倒序。

## 5. 改站点的基本信息

### 站名、描述、域名、邮箱

文件：`data/siteMetadata.js`

```js
title: '地球Online生存日记',      // 站名：页头、浏览器标签、分享卡片
description: '技术笔记与随笔…',    // 站点描述
siteUrl: 'https://dev-notes-dun.vercel.app',  // 必须和生产域名一致，末尾不要加 /
email: 'hello@example.com',      // 出现在 RSS 里，也用于关于页
```

> `siteUrl` 影响 sitemap、RSS 里所有链接、分享卡片的图片地址。绑了新域名记得改这一行。

### 导航菜单

文件：`data/headerNavLinks.ts`

```ts
{ href: '/collections', title: '合集' },
```

改 `title` 就是改显示文字；删掉一行就是去掉一个菜单项。

### 关于页

文件：`data/authors/default.mdx`

可以改名字、职业、邮箱、社交链接。

**放头像**：把照片放到 `public/static/images/`，然后在 frontmatter 里加：

```yaml
avatar: /static/images/avatar.jpg
```

不填会显示站名首字的圆形占位。

## 6. 不要手改的文件

这些是自动生成的，改了会被覆盖，或者会出错：

| 文件                 | 谁生成的                   |
| -------------------- | -------------------------- |
| `app/tag-data.json`  | 根据所有文章的标签自动统计 |
| `public/search.json` | 搜索索引                   |
| `public/feed.xml`    | RSS，构建时生成            |
| `.contentlayer/`     | 整个内容层                 |

## 7. 常见问题

**文章写了但不出现**
→ 检查扩展名是不是 `.mdx`；检查 `date` 有没有写、有没有带引号。

**文章多了会不会需要手动分页**
→ 不会。`/blog` 每页 5 篇，超过自动分页，`/blog/page/2` 这类地址会自己出现。

**本地能看到，线上看不到**
→ 大概率是 `draft: true` 忘了删。

**标签页 404**
→ 看看是否有别的文章把同一个标签写成了另一个大小写/写法，导致你点的是那个"空"标签。

**`yarn build` 报 `Cannot find module for page`**
→ `yarn dev` 还在跑。停掉再构建。

**改了文件名，旧链接打不开了**
→ 文件名就是 URL，改名等于换地址。已经发出去的文章尽量别改文件名。

**文章里想写大括号 `{}` 或尖括号 `<`**
→ MDX 里它们有特殊含义，会被当成代码/标签。可以用反引号包住，或者写 `&#123;` / `&lt;`。

**构建报错提到某个 `.mdx` 文件**
→ 通常是 frontmatter 的引号不配对，或正文里有个没闭合的标签。看报错行号。

## 8. 发布前检查清单

- [ ] `draft` 已删掉
- [ ] `summary` 写了（否则卡片上是空的）
- [ ] `tags` 用的是已有的写法，没制造近义标签
- [ ] 想进合集的话，`data/collections.ts` 里加上了
- [ ] 插图路径是 `/static/images/xxx`，文件确实在 `public/static/images/` 下
- [ ] 本地打开文章看了一遍（尤其是代码块和公式）
- [ ] `git push`
